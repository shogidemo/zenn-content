Claude Codeの5時間制限は、API料金に換算するとどれくらいの規模感なのでしょうか。

## TL;DR

私の環境で、Claude Codeの利用率表示とCLIのJSON出力を突き合わせ、5時間枠・7日枠がどれくらいのトークン構成に相当しそうかを測りました。

結果は以下です。

| 制限枠                          |    表示値ベースの推定 |  丸め誤差を考えた目安 |              API料金換算 |
| ------------------------------- | --------------------: | --------------------: | -----------------------: |
| 今回条件での5時間枠100%換算     |   約644万トークン相当 |        約633万〜656万 |      約$62（約$61〜$63） |
| 参考: 今回条件での7日枠100%換算 | 約8,859万トークン相当 | 約7,087万〜1億1,812万 | 約$850（約$680〜$1,134） |

計測条件は、Claude TeamプランPremiumシート、Claude Code CLI、`opus` / `xhigh`、実測モデルは `claude-opus-4-7` です。計測時間帯は2026年5月5日14:23〜14:31 JSTでした。

:::message alert
これはClaude Codeの利用制限をトークン数に変換する公式な式ではありません。

私のSeat、モデル、effort、プロンプト構成、キャッシュ比率で観測された利用率増分を、同じ構成が続くと仮定して外挿した値です。API料金換算も実請求額ではなく、「同じトークン構成をClaude APIの価格で流したらいくらか」という参考値として読んでください。
:::

## なぜ測ったのか

Claude Codeには利用制限があります。公式ヘルプでも、利用量は会話の長さ、添付ファイル、現在の会話量、使うモデルや機能によって変わり、セッションベースの利用制限は5時間ごとにリセットされると説明されています。

ただ、普段使っている側として知りたいのは、もう少し生々しい数字でした。

「5時間制限って、実際どのくらい使えるの？」

「自分はなぜ2時間くらいで100%まで使い切ってしまうの？」

「週次制限も4日目くらいで尽きるけど、どれくらい足りないの？」

「追加料金を払うとして、どれくらいの規模感なの？」

このあたりを把握しないまま使っていると、ずっと節約しながら作業することになります。必要なときは追加利用すればよいのですが、規模感が見えないまま追加し続けるのは落ち着きません。

そこで、Claude Codeの利用率がどれくらいのトークン量で増えるのかを測ってみました。

## 検証結果

今回の検証では、固定の大きめのプロンプトをClaude Codeに繰り返し投げ、開始前と終了後の利用率を比較しました。

5時間利用率は、7%から62%まで増えました。差分は+55ポイントです。

この間にClaude Codeが使ったトークンは以下でした。

| 種別                         | トークン数 |
| ---------------------------- | ---------: |
| 通常入力                     |         50 |
| キャッシュ作成               |  3,344,213 |
| キャッシュ読込               |    179,920 |
| 出力                         |     19,500 |
| 観測トークン合計（単純合算） |  3,543,683 |

この3,543,683トークンで5時間利用率が55ポイント増えたので、単純に100%へ線形換算するとこうなります。

```text
3,543,683 tokens * 100 / 55 = 6,443,060 tokens
```

つまり、今回の条件と同じトークン構成が続くと仮定すると、5時間枠100%は表示値ベースで約644万トークン相当に見えました。

同じ区間で、7日利用率は64%から68%まで増えました。差分は+4ポイントです。こちらも同じように線形換算すると、7日枠（週次制限）100%は表示値ベースで約8,859万トークン相当に見えます。

ただし、7日枠は差分が4ポイントしかありません。整数%表示の丸めだけでも大きく振れるため、5時間枠よりかなり粗い参考値として見ています。

整数%表示の丸めを考えると、目安は次の範囲まで広がります。

| 制限枠  | 表示上の差分 | 丸めを考えた差分の目安 |    トークン換算の目安 |
| ------- | -----------: | ---------------------: | --------------------: |
| 5時間枠 |  +55ポイント |        +54〜56ポイント |        約633万〜656万 |
| 7日枠   |   +4ポイント |          +3〜5ポイント | 約7,087万〜1億1,812万 |

## API料金に換算するとどれくらいか

トークン量だけだと直感的にわかりにくいので、API料金にも換算しました。

2026年5月6日時点のClaude pricingを参照し、Opus 4.7の入力、出力、キャッシュ作成、キャッシュ読込の単価を使って再計算しています。

今回使った単価は以下です。

MTokはMillion tokens、つまり100万トークンです。

| 種別                 |         単価 |
| -------------------- | -----------: |
| 通常入力             |    $5 / MTok |
| 5分キャッシュwrite   | $6.25 / MTok |
| 1時間キャッシュwrite |   $10 / MTok |
| キャッシュread       | $0.50 / MTok |
| 出力                 |   $25 / MTok |

今回のキャッシュ作成は、Claude Codeの出力上で `ephemeral_1h_input_tokens` として観測されました。そのため、5分キャッシュwriteではなく、1時間キャッシュwriteの単価で計算しています。

観測区間の内訳はこうなります。

| 種別                 | トークン数 |         単価 |      金額 |
| -------------------- | ---------: | -----------: | --------: |
| 通常入力             |         50 |    $5 / MTok |  $0.00025 |
| 1時間キャッシュwrite |  3,344,213 |   $10 / MTok | $33.44213 |
| キャッシュread       |    179,920 | $0.50 / MTok |  $0.08996 |
| 出力                 |     19,500 |   $25 / MTok |  $0.48750 |
| 合計                 |          - |            - | $34.01984 |

このように、今回のAPI料金換算はほとんどが1時間キャッシュwriteです。観測区間の約$34.02のうち約$33.44、つまり約98%を1時間キャッシュwriteが占めています。キャッシュ作成を5分キャッシュwriteとして計算すると金額が小さく出るため、ここを分けるのが重要でした。

つまり、今回のAPI料金換算で約$62相当という値は「大量の1時間キャッシュ作成を伴う使い方」をAPI価格に当てはめた結果です。出力トークンが多い作業、キャッシュreadがよく効く作業、Sonnetを使う作業では、同じ利用率増分でもAPI料金換算は大きく変わります。

| 制限枠                      | 表示値ベースのAPI料金換算 | 丸め誤差を考えた目安 |
| --------------------------- | ------------------------: | -------------------: |
| 観測区間                    |                     約$34 |                    - |
| 今回条件での5時間枠100%換算 |                     約$62 |           約$61〜$63 |
| 今回条件での7日枠100%換算   |                    約$850 |       約$680〜$1,134 |

Claude Codeが返すJSONにも `total_cost_usd` はありますが、これはローカル推定値として扱いました。今回の記事では、公式価格表ベースで再計算した値を主にしています。なお、上限到達後の追加利用では標準API価格が関係しますが、この記事で扱う「サブスクリプション枠のAPI料金換算」は実請求額ではありません。サブスクリプション枠の規模感をAPI価格で見た場合の参考値です。

この5時間枠のAPI料金換算で約$62相当という値は、私の体感ともそこまで離れていません。以前、制限が100%になった状態で追加利用に切り替えて使い続けたとき、1時間も経たずに$50を超えた記憶があります。もちろん、そのときの作業内容やキャッシュの効き方は今回と同じではありませんが、少なくとも今回の換算値が極端に現実離れしている印象はありませんでした。

## どうやって測ったか

### 認証と計測対象

Claude Codeは、Claude Teamのサブスクリプション認証で実行しました。`ANTHROPIC_API_KEY` によるAPIキー課金モードでは実行していません。

利用率は、ClaudeのSettings > Usageに表示されるPlan usage limitsの進捗バーと同等の値を記録しました。ただし、この値の取得方法は公式に安定保証されたAPIではないため、将来同じ方法で再現できるとは限りません。

この記事で扱う7日利用率は、保存したレスポンス上の `seven_day` 枠です。別途 `seven_day_sonnet` も取得できていましたが、今回の計測対象には含めていません。`seven_day` とUI上の週次バーの厳密な対応は未確認です。そのため、7日枠の換算値は5時間枠よりもさらに粗い参考値として扱っています。

大まかな流れは次の通りです。

1. 開始前にSettings > Usage相当の5時間利用率と7日利用率を保存する
2. 固定プロンプトをClaude Codeに複数回投げる
3. 5回ごとに利用率スナップショットを保存する
4. 5時間利用率が+50ポイント以上動いたら止める
5. Claude CodeのJSON出力からトークン内訳を集計する
6. 利用率差分から100%相当のトークン量へ線形換算する

Claude Codeのトークン内訳は、各実行のJSON出力に含まれる `usage` フィールドを集計しています。

今回の実行では10回成功し、5時間利用率が+55ポイント動いたところで停止しました。計測開始は2026-05-05 14:23:06 JST、終了は14:31:39 JSTなので、同じ5時間ウィンドウ内で完了しています。

## ccusageを参考にした

今回の検証では、Claude Codeのトークン消費やコストをどう扱うかを考えるうえで、OSSの[ccusage](https://ccusage.com/)を参考にしました。

ccusageは、Claude Codeがローカルに保存するJSONLファイルを読み、日次、週次、月次、セッション、5時間ブロック単位でトークン使用量や推定コストを集計できるツールです。キャッシュ作成トークンとキャッシュ読込トークンも分けて扱えるため、Claude Codeの利用量を見る発想としてとても参考になりました。

今回の記事で出している制限枠換算は、ccusageの出力そのものではありません。保存したスナップショットとClaude CodeのJSON出力をもとに、自分の検証用に集計・外挿した値です。

## この数字を一般化しすぎないために

今回の数字は、万能なClaude Code利用制限表ではありません。

今回の「約644万トークン相当」は、Claude Codeの5時間制限が常に644万トークンである、という意味ではありません。

利用制限は、モデル、effort、会話の長さ、機能、キャッシュの効き方、同じアカウントでの他Claude利用などに影響されます。今回の値は、Team PremiumシートでOpus 4.7 xhighを使い、1時間キャッシュ作成が大きく発生した固定プロンプトを繰り返した場合の観測値です。

なお、本記事では通常入力・キャッシュ作成・キャッシュ読込・出力を単純合算した「観測トークン合計」から利用率を外挿しています。ただし、Claude Codeのサブスクリプション利用率がこの単純合算トークン数で内部的に計算されている、という意味ではありません。実際の利用率は、モデル、機能、推論設定、キャッシュ、時間帯、その他内部要因によって重み付けされている可能性があります。

また、xhighでは、見えている出力以外にthinking由来のトークンが発生する可能性があります。この記事ではClaude CodeのJSON出力に含まれる `usage` を正として集計しており、見た目の出力量ではなく、`usage` 上の `output_tokens` を使っています。

したがって、実務でSonnetを使う場合、キャッシュreadが多い場合、出力が長い場合、サブエージェントや並列セッションを使う場合には、同じ利用率増分でもトークン内訳やAPI料金換算は変わります。

特に注意が必要なのは次の点です。

- プラン、モデル、推論設定、時期によって変わる可能性がある
- Claude Codeの利用率表示は整数%なので、丸め誤差がある
- 5時間制限は+55ポイント動かせたので比較的見やすいが、7日制限は+4ポイントなので粗い
- キャッシュ作成とキャッシュ読込の比率でAPI料金換算は大きく変わる
- Claude Codeのサブスクリプション制限とAPI課金は同一制度ではない
- 計測中に他のClaude利用が完全にゼロだったことは外部から証明できない
- Opus 4.7は新しいトークナイザーを使っており、同じテキストでも旧モデルとトークン数が変わる可能性がある

また、今回の利用率取得はClaude Codeの利用状況を観測するためのものです。公式に安定保証されたAPIとして扱うものではないため、再現性や将来の互換性には注意が必要です。

## 自分の使い方に当てはめる

今回の主な収穫は、私の環境・今回のトークン構成に限れば、「利用率55ポイント分がAPI価格換算で約$34、5時間枠100%へ外挿すると約$62相当」という目安が得られたことです。

たとえば、今回と同じトークン構成に近い重めの作業で5時間枠を2時間で使い切るなら、単純計算では1時間あたり約322万トークン相当のペースで消費していることになります。

週次枠についても、粗い推定ではありますが、表示値ベースで約8,859万トークン相当という参考値があると、4日で尽きるペースがどれくらい重いのかを考えやすくなります。

もちろん、実務のClaude Code利用は固定プロンプトの繰り返しとは違います。実際には、リポジトリの大きさ、読み込むファイル数、auto-compact、やり直し、レビューの往復などで消費量はかなり変わります。

それでも、何も数字がないよりはずっと判断しやすくなりました。

私の場合は、少なくとも「足りない気がする」ではなく、「この使い方だと5時間枠に対して明らかに速いペースで消費している」と言えるようになりました。追加利用するか、作業を分散するか、軽いモデルや別ツールを併用するかを考える材料になります。

## おわりに

Claude Codeの利用制限は、メッセージ数や時間だけで見ると実態がつかみにくいです。

今回の検証では、私の環境・今回のトークン構成における5時間枠は表示値ベースで約644万トークン相当、7日枠は表示値ベースで約8,859万トークン相当に見えました。API料金に換算すると、それぞれ約$62、約$850です。

繰り返しになりますが、これは実請求額ではなく、同じトークン構成をAPI価格で流した場合の換算値です。プランやモデルが変われば数字も変わります。

公式ヘルプ上の米国価格・税抜では、TeamプランのPremiumシートは月払いで月額$125です。今回のトークン構成をAPI価格に当てはめると、5時間枠だけで約$62相当、7日枠では表示値ベースで約$850相当になります。

もちろん、これはサブスクリプション枠をAPI価格で評価した場合の参考値であり、実請求額でも、Anthropicが内部的に同じ単価で制限を設計しているという意味でもありません。それでも、少なくとも私の今回の使い方では、サブスクリプション枠をAPI価格で見た場合の規模感はかなり大きい、という感覚は得られました。

一方で、これは定量的に検証したものではありませんが、体感としては以前より制限が厳しく感じる場面もあります。そこは少し寂しいところです。高性能モデルを日常的に使うほど、チームとしてのコスト管理は避けにくくなっています。できるだけコストを上げず、チームの生産性も落とさないようにしたい。今後は、限られた制限枠の中でどれだけ効率的にClaude Codeを使えるかが、ますます大事になりそうです。

それでも、利用制限に悩みながらClaude Codeを使っている人にとって、1つの目安にはなるはずです。私自身、これでようやく「どれくらい足りないのか」を少し落ち着いて見られるようになりました。
