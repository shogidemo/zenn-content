## TL;DR

- 応答時間はほぼ同じ（体感と違った）
- 品質もほぼ同じ（差は誤差レベル）
- 効率性（出力量/時間）はCodex CLIが優位だが、実用上は気にならない
- **どちらを使っても問題ない**

:::message alert
今回の検証は**レビュー用途**に限定しています。コード生成やコーディングのタスクは含めていません。生成タスクでは結果が異なる可能性があります。
:::

## きっかけ：業務でCodexが使えなかった

個人開発では、Claude Codeで書いた計画やコードを**Codex CLI**でレビューさせていました。別のAIの視点を入れることで、見落としを防げるからです。

ところが業務ではCodexが使えない環境でした。同じ方法が使えず困っていたところ、[@nuits_jp](https://zenn.dev/nuits_jp)さんの[GitHub Copilot CLIの記事](https://zenn.dev/nuits_jp/articles/2026-01-26-cheet-of-copilot)を読んで、「**Copilot CLIなら業務でも使える**」と気づきました。

「じゃあClaude CodeをCopilotでレビューすればいいじゃん！」

そう思って試してみたのですが、**タイムアウトがそこそこ発生した**んです。体感で10回に1〜2回くらい。同じGPT-5.2、同じreasoning effort（xhigh: 最も推論に時間をかける設定）を使っているのに、Codexではほぼタイムアウトしなかったのに。

「もしかしてCopilot CLIの方が遅い？」

そう思って、ちゃんと計測してみることにしました。

---

## 結果：体感ほどの差はなかった

先に結論を書きます。180回計測した結果、**平均応答時間に統計的な有意差はありませんでした**。ただし中央値はCopilot CLIの方が8.6秒速く、分布に偏りがある可能性があります。

正直、びっくりしました。体感では明らかにCopilot CLIの方が遅かったのに。

### 応答時間

| 指標   | Codex CLI | Copilot CLI | 差分             |
| ------ | --------- | ----------- | ---------------- |
| 平均   | 48.19秒   | 48.05秒     | -0.14秒（-0.3%） |
| 中央値 | 46.23秒   | 37.63秒     | -8.60秒          |
| p95    | 116.65秒  | 116.76秒    | ほぼ同等         |
| 成功率 | 100%      | 100%        | 同等             |

※成功率は正式計測（2026年2月1日）の結果。事前のトライアル時はCopilot CLIでタイムアウトが数回発生していました。

ペア差分析（同じプロンプトで両CLIを比較した90ペア）の95%信頼区間は[-5.37, 5.09]秒。ゼロを含んでいるので、統計的に有意な差とは言えません。

### 品質もほぼ同じ

応答時間だけでなく、出力の品質もほぼ同じでした。

| CLI         | 平均スコア（/30） |
| ----------- | ----------------- |
| Codex CLI   | 28.18             |
| Copilot CLI | 26.67             |

差分は+1.51点、約5%。正直、**誤差レベル**です。Claude Opus 4.5によるブラインド採点の結果ですが、この程度の差で「Codex CLIが優れている」とは言い切れません。

:::details 採点方法の詳細

- **採点者**: Claude Opus 4.5（AI自動採点）
- **方式**: どちらのCLIの出力か隠した状態で評価（ブラインド）
- **評価軸**: タスクごとに3軸を選定、各10点満点（計30点）
  - 例: explainタスク → 正確性・明瞭さ・完全性
  - 例: reviewタスク → 妥当性・建設性・具体性
    :::

評価軸別に見ると「明瞭さ」でCodex CLIの方が+1.67点高かったのですが、これも誤差の範囲でしょう。体感では両者に明確な差は感じませんでした。

### 効率性も違う

「秒/KB」（1KBの出力を得るのにかかる時間）で比較すると：

- Codex CLI: **16.5秒/KB**
- Copilot CLI: 25.7秒/KB

Codex CLIの方が**36%効率的**。Copilot CLIの応答時間が同程度に見えるのは、出力量が少ないためと考えられます。

※「KB」は出力テキストのバイト数（UTF-8）を基準に計算しています。

## 検証で困ったこと

### サンプル数の決定

最初は「10回くらいでいいだろう」と思っていました。でも実際に回してみると、ばらつきが大きすぎて信頼区間が広くなりすぎる。

結局180回まで増やすことになりました。各CLI 90回、5種類のタスク（コード説明、レビュー、計画レビュー、改善提案、バグ探索）で計測しています。

### reasoning_effortの設定

もう1つ困ったのが、reasoning_effortの設定方法です。

Codex CLIはコマンドオプションで明示できます：

```bash
codex exec -m gpt-5.2 -c 'model_reasoning_effort="xhigh"' "プロンプト"
```

Copilot CLIはconfig.jsonに書くしかなく、設定が反映されているか確認するのに手間取りました：

```bash
copilot --model gpt-5.2 -s -p "プロンプト"
```

両方ともxhighで統一したつもりですが、完全に同一条件かは正直自信がありません。

## なぜ体感と違った？

「Copilot CLIでタイムアウト頻発」と「統計的に有意差なし」。この矛盾をどう説明するか。

### コールドスタート vs ウォーム

各プロンプト×タスク種類の組み合わせにおいて、1回目の実行を「Cold」、2回目以降を「Warm」として分析しました。ここでの「Cold」はプロセス起動からAPIキャッシュが効いていない状態、「Warm」はキャッシュやコネクションが再利用される可能性がある状態を指しています。

| 種別              | Codex CLI | Copilot CLI |
| ----------------- | --------- | ----------- |
| Cold（1回目）     | 48.30秒   | **35.88秒** |
| Warm（2回目以降） | 48.17秒   | 49.40秒     |

これは面白い結果でした。**Copilot CLIはコールドスタートが約12秒速い**んです。でもウォーム状態だと逆転して、Codex CLIと同等かやや遅くなる。

私の使い方は「Claude Codeで書いた計画をレビューさせる」という単発利用（＝コールドスタート）が多かったので、本来ならCopilotの方が速いはず。でも体感では遅かった。コールドスタート/ウォームの違いだけでは、タイムアウト頻発の説明がつきません。

### タイムアウトの原因は？

タイムアウトが多かった理由として考えられるのは：

1. **出力量の違い**: Copilot CLIは出力量が少ない傾向があり、長い出力を求めると時間がかかる
2. **APIの負荷状況**: 正式計測（2026年2月）と事前のトライアル時で状況が違った可能性
3. **私の設定ミス**: reasoning_effortが正しく反映されていなかった可能性

正直、はっきりした原因はわかりません。ただ、計測してみると「Copilot CLIが遅い」という私の体感は、少なくとも今回の条件では裏付けられませんでした。

## おわりに

「同じモデルならどちらでも同じ」と思っていましたが、微妙な違いがありました。

私の結論：

1. **応答時間・品質ともに実用上の差は小さい** - どちらを選んでも問題ない
2. **単発利用ならCopilot CLI** - コールドスタートが12秒速い
3. **継続利用ならCodex CLI** - ウォーム状態での安定感、効率性が良好
4. **どちらでもp95は約2分** - 最悪ケースも同様

今回の結果を受けて、**業務ではCopilot CLIで全然問題ない**と感じました。しばらくCopilotを使い続けてみて、もし「やっぱり遅いな」と感じたら、検証方法を見直してまた計測してみます。

個人開発ではCodex CLIに慣れているのでそのまま使っていますが、正直どちらでもよいです。

## 計測条件

この結果は以下の条件に依存します。

- 計測日: 2026年2月1日
- Codex CLI: 0.93.0 / Copilot CLI: 0.0.400
- モデル: GPT-5.2（reasoning_effort: xhigh）
- 計測回数: 180回（各CLI 90回）
- タスク: explain、review、plan-review、code-improve、bug-find
- 環境: macOS、同一マシン
- **対象: レビュー用途のみ（コード生成は含まない）**

:::details 計測方法の詳細

- **計測方法**: シェルスクリプトで各CLIを呼び出し、`time` コマンドで実行時間を記録
- **タイムアウト定義**: 180秒を上限とし、超過した場合は計測から除外（今回の正式計測では発生せず）
- **統計手法**: 対応のあるt検定（ペア差分析）で有意差を検証。95%信頼区間を算出
- **品質採点**: Claude Opus 4.5にJSON形式で出力させ、自動集計
  :::

:::message alert
「同じGPT-5.2」と書いていますが、CLIごとにシステムプロンプトや既定パラメータ（temperature、max_tokens等）が異なる可能性があります。モデル名が同一でも、実装・設定差で結果が変わり得る点にご注意ください。
:::

他のタスク・環境・時期では結果が異なる可能性があります。
