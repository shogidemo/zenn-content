# 記事レビュー

Zenn記事の品質を多角的にレビューする。

## チェック手順

1. 対象記事ファイルを読み込む（指定がなければ直近編集中の記事を自動検出）
2. 以下の6観点でチェックを実施
3. `/ask-codex` でCodexにレビューを依頼（**必須・スキップ禁止**）
4. Codexの指摘を確認・精査し、採否を判断
5. 最終的なレビュー結果をまとめて出力

## 6つの観点

### A. 読者視点

- 対象読者が明確（「誰向け」「何が得られるか」が冒頭で分かる）
- 読者メリットが具体的
- 前提知識が明示されている

### B. 内容の正確性

- コード・コマンドが動作する
- バージョン情報が明記されている
- 再現可能な手順になっている
- 環境情報（OS、言語バージョン等）が明記されている

### C. 引用・出典

- 外部情報は出典URLを記載
- 公式ドキュメントへのリンクがある
- **外部リンクは日本語版を優先**（/ja/ 版があれば使用）
- 画像・コードのライセンスが適切

### D. 構成・読みやすさ

- 論理的な流れ（導入→課題→解決→結果）
- 適切な見出し階層（h2から開始）
- 段落が長すぎない（目安: 3-5文）
- コードブロックに言語指定・ファイル名がある

### E. SEO・発見性

- タイトル60文字以内
- topics適切（関連性のあるタグ、最大5つ）
- 検索キーワードが含まれている

### F. Zenn固有

- Front Matter完備（title, emoji, type, topics, published）
- Zenn記法活用（:::message, :::details等）
- 画像にaltテキストがある

## Codexレビュー（必須）

`/ask-codex` で以下を依頼：

```
この記事をレビューしてください。以下の観点でフィードバックをお願いします：
1. 記事の論理構成は適切か
2. 技術的な説明に不正確な点はないか
3. 読者視点で分かりにくい箇所はないか
4. 改善すべき点があれば具体的に指摘してください
```

**Codexの指摘は参考意見として扱い、最終判断はClaude Codeが行う。**

| 採用                 | 不採用                     |
| -------------------- | -------------------------- |
| 読者視点で有効な指摘 | Zennのトーンと合わない     |
| 技術的な誤りの指摘   | このリポジトリの方針と矛盾 |
| 見落としていた観点   | 根拠が不明確な指摘         |
