# 炎上チェック

記事が炎上するリスクを事前にチェックし、問題となりうる表現や内容を指摘する。

## チェック手順

1. 対象記事ファイルを読み込む（指定がなければ直近編集中の記事を自動検出）
2. 5つの炎上パターンに照らしてチェック
3. リスク評価と修正提案をレポート出力

## 5つの炎上パターン

### 1. 顧客不在のHard Things自慢

失敗談・苦労話で「顧客への対応」が欠落していないかチェック。

```
NG: 「チームで協力して乗り越えました」（顧客への言及なし）
NG: 「クレームが来ましたが、社内では〜」（顧客対応の説明なし）
OK: 「お客様には〜で対応し、〜という形で解決しました」
```

### 2. マサカリ誘発表現

断定的・攻撃的な表現がないかチェック。

```
NG: 「すべてのエンジニアはTypeScriptを使うべきだ」
NG: 「JavaScriptはもう時代遅れだ」
NG: 「〜は常識だ」「〜は間違い」
OK: 「私のチームでは〜が効果的でした」
OK: 「個人的には〜という印象を持っています」
```

**特に注意**: 言語・フレームワーク・エディタの比較、キャリア論

### 3. 機密情報・個人情報漏洩

- 社内プロジェクト名・システム名が伏せられているか
- 顧客名・取引先名が匿名化されているか
- APIキー・認証情報がコードに含まれていないか
- 個人を特定できる情報がないか

### 4. 上から目線・マウンティング

```
NG: 「これを知らないエンジニアはヤバい」
NG: 「こんな基本的なことも知らないの？」
NG: 「素人はこういうミスをしがち」
OK: 「私も最初は知りませんでしたが〜」
OK: 「意外と見落としがちなポイントとして〜」
```

### 5. 誤情報・未検証情報

- 動作確認せずに書いたコードがないか
- 古い情報を最新と誤認させていないか
- 出典のない統計データがないか
- 伝聞情報を事実として書いていないか

## リスク評価基準

| レベル      | 説明                   | 対応                 |
| ----------- | ---------------------- | -------------------- |
| 🔴 高リスク | 炎上する可能性が高い   | **公開前に必ず修正** |
| 🟡 中リスク | 批判を受ける可能性あり | 修正を推奨           |
| 🟢 低リスク | 軽微な指摘の可能性     | 可能なら修正         |

## 出力フォーマット

```markdown
# 炎上チェック結果

## 総合リスク評価

🟡 中リスク

## 検出された問題

### 🔴 高リスク

1. **マサカリ誘発表現**（行XX）
   - 問題: 「すべてのエンジニアは〜すべき」
   - 修正案: 「私の経験では〜が効果的でした」

### 🟡 中リスク

1. **上から目線表現**（行XX）
   - 問題: 「〜を知らないのはありえない」
   - 修正案: 「意外と見落としがちな〜」

### 🟢 低リスク

- なし

## パターン別チェック結果

| パターン              | 結果      | 詳細 |
| --------------------- | --------- | ---- |
| 顧客不在のHard Things | ✅ OK     | -    |
| マサカリ誘発表現      | ⚠️ 要確認 | 2件  |
| 機密情報漏洩          | ✅ OK     | -    |
| 上から目線            | ⚠️ 要確認 | 1件  |
| 誤情報・未検証        | ✅ OK     | -    |
```
