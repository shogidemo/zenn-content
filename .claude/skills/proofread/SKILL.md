# 校正チェック

記事の文章品質を校正・チェックする。

## チェック手順

1. 対象記事ファイルを読み込む（指定がなければ直近編集中の記事を自動検出）
2. 4つの観点で校正チェックを実施
3. 修正箇所と修正案をレポート出力

## 4つの観点

### 1. 誤字脱字

よくある誤字パターン：

| 誤         | 正             |
| ---------- | -------------- |
| 以外と     | 意外と         |
| 的を得た   | 的を射た       |
| させて頂く | させていただく |
| ～の様な   | ～のような     |
| 出来る     | できる         |

### 2. 表記ゆれ

**文体の統一:**

- 「です・ます」調と「だ・である」調が混在していないか

**技術用語:**

| 正         | 避ける          |
| ---------- | --------------- |
| GitHub     | Github, GITHUB  |
| JavaScript | Javascript      |
| TypeScript | Typescript      |
| Node.js    | NodeJS, node.js |
| VS Code    | VSCode, vscode  |

**数字表記:**

- 半角数字で統一
- 桁区切りのルールを統一

### 3. 文法

- 主語と述語が対応しているか
- 二重否定になっていないか
- 一文が長すぎないか（目安: 80文字以内）

**冗長表現の修正:**

| 冗長             | 簡潔   |
| ---------------- | ------ |
| することができる | できる |
| ～という形で     | ～で   |
| まず最初に       | まず   |
| 約～ぐらい       | 約～   |

### 4. 句読点

- 読点（、）の位置が適切か
- 箇条書きの末尾の句点が統一されているか

## 出力フォーマット

```markdown
# 校正チェック結果

## 検出件数サマリー

| カテゴリ | 件数 |
| -------- | ---- |
| 誤字脱字 | 2件  |
| 表記ゆれ | 3件  |
| 文法     | 1件  |
| 句読点   | 0件  |

## 修正が必要な箇所

### 誤字脱字

1. 行15: 「以外と」→「意外と」

### 表記ゆれ

1. 「Github」と「GitHub」が混在
   - 行8: Github → GitHub

### 文法

1. 行55: 「することができます」→「できます」

### 句読点

- 問題なし
```
