# Planレビューワークフロー

計画（plan）を作成した際の品質保証ルール。
**実装開始前の最終工程**として、Codexへのレビュー依頼を行うこと。

---

## 必須ルール

### 1. planの最後にCodexレビューステップを含める

plan作成時、**実装開始前の最終工程として「Codexへのレビュー依頼」を入れること**。

:::message
Codexレビューは「実装後」ではなく「実装開始前」に行う。
レビュー結果を踏まえてplanを更新してから実装に入る。
:::

```markdown
## 計画

1. 〇〇の調査
2. △△の実装
3. □□のテスト
4. **Codexにplanをレビュー依頼**（実装開始前に実施）
```

### 2. Codexレビューの実行

`/ask-codex` を使用して、作成したplan全体のレビューを依頼する。

**依頼内容に含めるべき情報：**

- **スコープ**: 今回の対象範囲
- **非スコープ**: 対象外の事項
- **制約**: 技術的制約、時間制約など
- **前提**: 既存のコードベース、環境など
- **完了条件**: 何をもって完了とするか

**依頼内容の例：**

```text
以下のplanをレビューしてください：

[planの内容]

スコープ: ルールファイルの追加とCLAUDE.mdへの参照追加
非スコープ: settings.jsonの変更、他のルールファイルの修正
制約: 既存のルール構造との整合性を保つ
前提: 記事作成フローでは既にCodexレビューが必須化されている

確認観点：
1. 実装の実現可能性に問題はないか
2. 漏れているタスクや考慮事項はないか
3. タスクの順序・依存関係は適切か
4. リスクや懸念点はないか
```

### 3. レビュー回数の制限

- **原則1回**: 1つのplanにつきCodexレビューは原則1回
- **再実施条件**: planを大幅に変更した場合のみ再度レビューを依頼

:::message alert
無限ループを防ぐため、軽微な修正でCodexレビューを繰り返さないこと。
:::

### 4. 最終判断はClaude Codeが行う

:::message alert
**Codexの指摘は常に正しいとは限らない。**
Codexの意見は「参考意見」として扱い、**最終的な採否判断はClaude Codeが行う**こと。
:::

**判定基準：**

- 指摘が論理的で、planの改善に寄与する → **採用**
- 指摘がコンテキストを理解していない、または不適切 → **不採用**
- 判断に迷う場合 → **ユーザーに確認**

**出力形式：**

| Codexの指摘      | 採否      | 理由                             |
| ---------------- | --------- | -------------------------------- |
| 〇〇を追加すべき | ✅ 採用   | 漏れていた重要な考慮事項         |
| △△は不要         | ❌ 不採用 | ユーザーの要件を満たすために必要 |

---

## 適用タイミング

以下の場合にこのワークフローを適用する：

- [ ] Plan mode で計画を作成した場合
- [ ] 複雑なタスクの実装計画を立てた場合
- [ ] ユーザーから「計画を立てて」と依頼された場合

**スキップする場合は理由を明記：**

単純なタスクや調査のみのタスクではスキップ可能だが、その場合は理由を明記すること。

```markdown
## Codexレビュー

スキップ（理由: 単一ファイルの軽微な修正のため）
```

---

## 実行例

```markdown
## Codexレビュー結果

/ask-codex を実行し、planのレビューを依頼しました。

### Codexからの指摘

1. ステップ2の前にバックアップを取るべき
2. エラーハンドリングの考慮が不足
3. テストケースを追加すべき

### 採否判定

| 指摘               | 採否      | 理由                                 |
| ------------------ | --------- | ------------------------------------ |
| バックアップ追加   | ✅ 採用   | 安全性向上のため妥当                 |
| エラーハンドリング | ✅ 採用   | 漏れていた重要な観点                 |
| テストケース追加   | ❌ 不採用 | 今回のスコープ外（ユーザー確認済み） |

### 更新後のplan

（Codexの採用した指摘を反映したplan）
```
